# Release and Nix acceptance criteria

- This flake is downstream of **OMP Lite**. A fresh install or `nix profile upgrade --refresh` from `main` must select the newest stable, verified Lite release (highest upstream version, then packaging revision). `config/nix-release.json` is generated from the published tag and all four GitHub asset digests; do not bump it by hand, point it at upstream OMP binaries, or remove the hashes to make it float.
- A release change is not verified by building the binary alone. Run `python3 scripts/release.py prepare` in an isolated checkout against the latest stable upstream, then build with `./build.sh --edition lite --strict-host`. PR and release CI must use the same preparation and candidate checks on macOS ARM64/x64 and Linux ARM64/x64. Each candidate must install through the flake in an isolated Nix profile, report the expected `omp --version`, and load the flake's extension SDK probe. **Only Intel macOS Nix setup and install are advisory**; report failures, but still require and ship the verified native Intel Lite binary.
- Lite publication requires all four candidates to pass. Nix must reconcile the tag and all asset hashes even if the release already exists and no build runs. A draft, incomplete release, dry run, or optional Portable failure must never select an unverified release or leave a publishable Lite release waiting on Portable.
- After an authorized rollout, verify the hosted release and Nix reconciliation jobs, compare `main`'s pin to the published release assets, and exercise a fresh install or profile refresh. If you cannot publish or only verified locally, say so; a local build, commit, or newer flake revision alone does not update users.
