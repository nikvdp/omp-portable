# Release and Nix acceptance criteria

- This flake is downstream of **OMP Lite**. A fresh install or `nix profile upgrade --refresh` from `main` must select the newest stable, verified Lite release (highest upstream version, then packaging revision). `config/nix-release.json` is generated from the published tag and all four GitHub asset digests; do not bump it by hand, point it at upstream OMP binaries, or remove the hashes to make it float.
- PR and release CI share the same latest-upstream preparation and native Lite checks on macOS ARM64/x64 and Linux ARM64/x64. A build or publication change needs `python3 scripts/release.py prepare` in an isolated checkout against the latest stable upstream, then `./build.sh --edition lite --strict-host`. All four verified native Lite binaries are required for publication. **No Nix or Portable job may gate or delay Lite publication.**
- Nix pin reconciliation and install validation run in their own downstream workflow; their failures must be visible there and must not block Portable either. Reconcile the published tag and all asset hashes even when an existing release is skipped. A dry run, draft, or incomplete release must not advance the pin. Check installation in an isolated profile, the expected `omp --version`, and the flake's extension SDK probe. PRs also check Nix separately against their candidate artifacts.
- After an authorized rollout, verify the hosted Lite release and downstream Nix workflow, compare `main`'s pin to the published release assets, and exercise a fresh install or profile refresh. If you cannot publish or only verified locally, say so; a local build, commit, or newer flake revision alone does not update users.
